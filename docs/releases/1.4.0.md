# [1.4.0] - 2025-07-01

## Enhamcements

- **Saved Prompts (MVP)**
  - Users can create, edit, delete, and use reusable prompts via the new “Prompts” section.
  - Full CRUD support with familiar UI/UX patterns.
  - Responsive prompt list/table with search and pagination.
  - “Use” workflow: Allows user to refine/edit a saved prompt in a large, form-friendly textarea before starting chat.
  - Direct “Start Chat” from prompt, optionally with chosen model.

- **Improved Prompt-to-Chat Workflow**
  - "Use" now opens a refinement page for the prompt, rather than dropping straight into chat.
  - Form supports full prompt editing and direct handoff to chat.
  - Model selection on "Use Prompt" page (select from all registered models).
  - Model choice is preserved and used on chat startup.

- **Dynamic Model Registry Integration**
  - Chat model dropdowns now generated dynamically from the Python `MODEL_REGISTRY` (single source of truth).
  - Default model is also controlled from the model registry, not hardcoded.
  - DRY pattern ensures any future model addition appears everywhere instantly.

- **Dashboard Integration**
  - New “Recent Prompts” dashboard card shows the user’s 5 most recently updated prompts, with links to use/refine each.
  - “View All” link to full prompt management page.
  - Section uses the same clean patterns as conversations, tags, notifications, and tickets.

- **Responsive & Consistent UI**
  - Prompt table fully responsive (mobile/tablet/desktop) using new `prompt.css`.
  - Search box, pagination, and controls patterns shared and unified between prompts and conversations modules.
  - Inline styles purged from prompt, tag, and related templates in favor of external CSS.
  - Modal confirm for deletes uses centralized, branded Syvrona modal.

- **Testing & QA**
  - Unit tests added for prompt CRUD, access control, and edge cases.
  - Tests updated to avoid deprecated SQLAlchemy patterns (now use `db.session.get()`).
  - Test suite passes with no warnings, clean run under Docker and native.

## Model & Database Changes

- **Database migration required. Run all Alembic/Flask-Migrate migrations as part of this deployment.**
- New data models and association tables were introduced for saved prompts, prompt chains, and prompt/chains tagging:

  - **Prompt Model (`prompt`)**  
    - New table for user prompts:  
      - `id` (PK), `user_id` (FK), `title`, `description`, `body`  
      - `is_public`, `is_staff`, `approved` flags  
      - `created_at`, `updated_at` timestamps  
    - Relationships:  
      - `user` (owner, FK to user table)  
      - `tags` (many-to-many, via `prompt_tags`)

  - **PromptChain Model (`prompt_chain`)**  
    - New table for reusable, shareable chains of prompts (for upcoming chaining features):  
      - `id` (PK), `user_id` (FK), `title`, `description`, etc.  
      - `is_public`, `is_staff`, `approved`, `created_at`, `updated_at`  
    - Relationships:  
      - `user` (owner, FK to user table)  
      - `prompts` (ordered many-to-many, via `chain_prompts`, includes `position` for sequence)
      - `tags` (many-to-many, via `chain_tags`)

  - **Association Tables:**  
    - `chain_prompts` (prompt ordering in chains):  
      - `chain_id` (FK), `prompt_id` (FK), `position` (int, NOT NULL)  
    - `prompt_tags` (tags on prompts):  
      - `prompt_id` (FK), `tag_id` (FK)
    - `chain_tags` (tags on prompt chains):  
      - `chain_id` (FK), `tag_id` (FK)

- **No changes to the User, Tag, or Conversation models in this release.**

- **Important:**  
  - All migrations are backward-compatible with production data.
  - Tagging and prompt chaining features are not yet user-visible but their schemas are in place and tested.

- **Steps to apply migrations:**  
  - Run: `flask db upgrade` (or your project’s Alembic equivalent)
  - Restart any running worker/background services that may use the models

- **Schema Version:**  
  - Bumped to support prompt and chain features for 1.4.0.

## Notable Internal/Technical Improvements

- Model selection and registry logic centralized in `model_registry.py`, eliminating hardcoded model lists in templates.
- DRY principle further enforced in prompt, chat, and use-prompt UIs.
- Reusable, shared CSS for search boxes, pagination, and form controls.
- “Auto-submit” logic for prefilled prompt (refined-prompt flow) can be toggled with a simple JS flag for dev/testing.

## Known Limitations & Future Work

- **Prompt tagging** and **multi-step (chained) prompt support** are NOT included here, but will be addressed in release 1.4.1.
- “Save as new” for prompt refinement is not yet enabled; current workflow overwrites existing prompt.
- Some further DRY opportunities exist for notification and tag cards in the dashboard (to revisit).
- No i18n/l10n changes in this release.
