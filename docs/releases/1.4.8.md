## ✨ New Features & Enhancements

- **#119 - Request-rate limiting (Flask-Limiter + Redis)**  
  Per-plan burst & daily limits configured via `RATE_LIMIT_TIERS` (e.g. `{"free":"5 per minute;100 per day","pro":"60 per minute;3000 per day"}`) and enforced on every `/answer` request. Returns **HTTP 429** (“Too Many Requests”) when exceeded.

- **#120 - Monthly token-quota enforcement**  
  New decorator `@enforce_token_quota` checks the `usage_stat` table before processing a chat. If the user exceeds their plan’s monthly quota (`TOKEN_QUOTAS`, e.g. `{"free":50000,"pro":1000000}`) the endpoint returns **HTTP 402**.

- **Real-time token counting**  
  Token counts (prompt + completion) are calculated during streaming with **tiktoken** using the model’s declared `encoding` (`cl100k_base` by default). Counts are written atomically to `usage_stat`.

- **Tokenizer helper**  
  `app/tokenizer.get_tokenizer(model_name)` centralises encoding lookup, falling back to `cl100k_base` when unspecified.

## 🧹 Architecture Improvements

- **Single-responsibility separation**  
  Providers stream tokens only; `AIStreamer` handles persistence and quota.  
- **Atomic counter update**  
  `_inc_usage()` performs `UPDATE tokens = tokens + :inc` with fallback `INSERT`, guarded by a `(user_id, period_start)` unique constraint.  
- **Decorator order rationalised**  
  `@limiter.limit` → `@login_required` → `@require_active_subscription` → `@enforce_token_quota` for cheapest-first short-circuiting.
